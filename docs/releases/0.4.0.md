# Ferrender 0.4.0

Ferrender 0.4.0 makes meshes a first-class body kind, names faces and edges by how they were made, adds a file container with a geometry cache, and adds Rhai scripts with a Scripts menu and a command-line runner.

- **Large meshes:** Import Mesh reads STL, OBJ and 3MF, streaming the file and sharing vertices as it goes, and repairs the result (degenerate and duplicate triangles dropped, orientation made consistent, closed shells turned outward) with a report. Meshes are indexed, picked through a bounding-volume hierarchy, drawn from indexed GPU buffers, and bodies over two million triangles draw a coarse copy while the view moves. In the review, the 3.5 million triangle Beethoven scan imported in 1.44 s, saved in 0.45 s and reopened in 0.32 s. Opt-in synthetic 5 M and 12 M triangle import/save/reopen tests also pass; these timings do not measure viewport or editing performance. See the review report for memory, hardware and test conditions.
- **Mesh editing:** the Mesh menu adds Repair (with hole filling), Decimate (quadric edge collapse, or clustering for huge scans), Smooth (Taubin), Subdivide (Loop or midpoint), Cut by a plane (capped, one side or both), Mirror, Offset / Thicken (a closed shell becomes hollow, an open surface becomes a printable solid) and Sculpt (pull, push, inflate, smooth, flatten brushes; each click is a stroke in the timeline). Relief from Image builds a height field from a photo or a depth map; inverted and thin it is a lithophane. Over the command API the same operations take regions (sphere, box, plane side, normal cone, connected shell) and `mesh_measure` reports shells, open edges, watertightness, volume, area and wall thickness. Every operation is a timeline feature. Undo and later edits can rebuild earlier operations, so their cost still depends on mesh size and the operation.
- **Mesh Booleans:** the old BSP is replaced by pinned `manifold-rust` 0.16.0, using symbolic perturbation with exact rational arrangements for self-intersections and precision failures. Union, cut and intersection preserve indexed topology. Stored f32 results are checked for closed, consistently oriented manifold geometry; invalid inputs or exceeded budgets produce an error and preserve the original design. Tests cover curved intersections, cavities, touching solids, rotated overlaps and save/export round trips.
- **Faces and edges by name:** sketch entities, primitive roles, generated-face ancestry and split boundaries identify geometry independently of kernel face order. Kernel history survives Boolean face cleanup. Fillets, shells, holes, thread tools, text and face planes retain proven references through edits; pattern copies stay distinct. Removed or ambiguous references report an error. Legacy picks migrate only at a unique original location; unsupported generated topology uses a conservative signature and can require reselection after shape changes.
- **File container and geometry cache:** images and indexed meshes live alongside `design.json`, a manifest, optional cache and thumbnail in a ZIP container. Locally saved evaluated geometry is authenticated with HMAC-SHA256 and a private installation key, in addition to design CRC, kernel/revision, volume and bounds checks. Unsigned, foreign or altered compatible files rebuild from their source timeline; they cannot authenticate themselves by supplying matching cache metadata. A future-format file is an explicitly **unverified read-only preview**, including in API results and exported STL/STEP provenance. The first converting save keeps `name (0.3 backup).ferr`. [FILE_FORMAT.md](../FILE_FORMAT.md) specifies the format.
- **Sweep:** Model → Sweep (and the `sweep` command) carries a closed profile along a path drawn in another sketch. Lines, arcs and splines that meet tangentially are followed exactly, sharp corners are mitred like a picture frame, a closed path gives a ring or a frame, and the profile either follows the path or keeps a fixed orientation. A sweep can cover only parts of its path, set with handles on a track in the dialog or as fractions over the API (`"spans": [[0.1, 0.3], [0.6, 0.7]]`). The result is an exact body with named faces, so it fillets, shells, patterns and exports to STEP like an extrusion. Every sweep is checked against the volume it must have, and one the kernel would get wrong is refused with the reason.
- **Scripts:** Rhai scripts with declared inputs run from the Scripts menu through an inputs dialog, on a worker thread with progress and Cancel, as one undo step, leaving a chip in the timeline that owns what the run made and can re-run with new inputs, detach or delete. A script's `confirm` and `ask` are answered in the progress window. Every command of the API is a function in a script; files are reachable only in the script's folder, the design's folder and folders you allow, those folders are walked without following links when a file is used, and everything a script writes is staged beside its target and moved into place only when the run succeeds. `run_script` and `ferrender run` take a time limit. Stable `output_key` values preserve downstream references when script output order changes; repeated modeling calls must have unique keys. Six samples ship (export variants of a parameter, export a folder of designs, a spur gear, bosses at sketch points, a CI check, a face relief); Export Timeline as Script turns a design into a generator. Headless, `ferrender run` and `ferrender check` serve CI, and MCP gains `list_scripts` and `run_script`.

- **Large assemblies:** a rebuild no longer copies every body for every feature, so rebuild time grows with the work the features do rather than with features × bodies (400 separate boxes: 3.6 s before, 0.33 s now; an 878-feature, 638-body assembly: 21.5 s before, 5.3 s now, on the same Apple Silicon Mac). Showing or hiding a body, sketch, plane or component, activating a component, renaming a feature, and undoing or redoing those steps keep the built bodies instead of rebuilding. A save that wanted a geometry cache but could not write one (modeled threads, geometry over the 32 MiB limit, feature errors) now says why, in the save message and in the `save` command's `cache_skipped`. Edge and face references made from a reported or clicked point are kept on the edge or face itself, so `"edges": "all"` and single picks resolve edges that share a tag, such as the two curves where one cut face meets a body.

- **Sketching:** points drawn within a few pixels of a sketch axis land on it and stay there (a horizontal or vertical constraint to the origin), so a revolve profile closes on its axis instead of just past it; a revolve that is refused says which axis, by how far and which points lie across it; the Revolve dialog rings those points in the viewport and offers the fixes that apply: switch to an axis the profile does not cross, or move the points onto the axis when they are within 2 mm of it. The Spline tool keeps going from its end like the Line tool, each further three clicks adding another four-point spline that shares the end point, until Escape or an existing point; clicking an existing point before the fourth click finishes the spline there, with the missing fit points spread along the last stretch. The Construction toggle sits beside the drawing tools. In a sketch, Move (M) is a sketch tool: drag a point or entity to move it, or select geometry and drag anywhere to move it all; spline fit points drag like any other point. Dragging a new or edited construction plane no longer rebuilds every body on each step. Section Analysis can cut along a construction plane as well as a world plane. Sliding along a line, the point sticks at its midpoint, with a marker, and a point placed there is held by a midpoint constraint. The Construction button shows whether the selected lines are construction and turns them back to normal. New geometry snaps onto a spline's curve (placed there, not tied to it: the solver has no point-on-spline relation yet), spline fit points are drawn as filled handles, and hovering a spline shows its numbered fit polygon. Applying a Shell says what it did, since a hollowed body looks the same from outside. A shell opened at a flat face whose edges were filleted now actually opens: the kernel's thick solid kept such a face and sealed an offset of it underneath, so Ferrender detects the kept face, hollows the body into a sealed shell and cuts the cap away through the face's outline instead; a non-flat face it cannot open is refused with the reason.

## Compatibility and known limits

Older designs remain readable. The container is format 9, face and edge tags format 10, mesh operations and reliefs format 11, script runs format 12, semantic tags and persistent script output keys format 13; a plain design that uses none of these is still written at its old version. Older apps refuse newer formats rather than silently omit features, except that 0.4 shows newer files read-only from their cache.

Mesh Booleans are bounded to 8 million input triangles combined, 2 million intersecting candidate pairs per check, 16 million output triangles and a cooperative 60-second deadline. Those are work limits, not an OS memory/process sandbox. Finite-precision output and invalid topology can still require changing or repairing a model. Local cache authentication proves this installation saved the bytes; it is not publisher authentication and does not protect against access to the private key. Source timelines remain authoritative. A sweep path must lie in one sketch plane (no helix or 3D path), corners are mitred rather than rounded and may turn by at most 150 degrees, and the profile cannot twist or scale along the path. Individual face highlighting is disabled on the indexed rendering path above 200,000 triangles; picking and whole-body selection still work. Subdivision applies to a whole mesh, not a region. Relief images are normalised to 8 bits, so a relief has 256 height levels; a 16-bit depth map loses precision. Reliefs from a plain photograph use its brightness as height, which is a lithophane, not a likeness; a depth map made elsewhere gives a bas-relief. Script shortcuts (`META.shortcut`) are not bound to keys yet. Scripts run in the app's own process: Cancel and the time limit take effect at the script's next operation, so a modeling call already under way runs to its end (the progress window then offers to stop waiting and discard the result), and there is no per-script memory budget beyond the mesh and script limits. The file sandbox bounds the script itself, not another program running as the same user. Undo does not remove files a finished run wrote. Export Timeline as Script still refuses a design whose features cannot be written as Rhai literals (for example integers beyond 64 bits) or whose script would exceed 1 MB after large meshes and images have gone to sidecar files. The geometry cache is keyed on the whole design, so any edit rebuilds from scratch as before. Vertex picks for three-point planes and hole entry points stay position-based. Bodies with modeled threads are not cached.

## Verification and documentation

The independent 0.4 review added regressions for geometry correctness, script isolation and history, hostile containers, cache invalidation and native rendering. See [the review report](../REVIEW_0.4.0.md) for the final test counts, model-building evidence, compatibility checks and remaining limits. Automated native UI tests and direct product operation are distinguished there; Linux/Intel validation is not inferred from Apple Silicon results.

See the [manual test plan](../TEST_PLAN_0.4.0.md), the [file format](../FILE_FORMAT.md), the [0.4 plan with what shipped](../0.4-release.md) and the [face relief tutorial](../tutorials/FACE_RELIEF_0.4.md).

Release packaging targets **Apple Silicon macOS**, **Intel macOS**, and **Linux x86-64**, with SHA256 checksums, documentation, and dependency notices. Linux builds target Ubuntu 24.04 and require glibc 2.39 or newer. macOS builds are ad-hoc signed, not notarized. Use **Help → About Ferrender → Copy build info** to verify version and source commit.
