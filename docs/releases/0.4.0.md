# Ferrender 0.4.0

Ferrender 0.4.0 makes meshes a first-class body kind, names faces and edges by how they were made, adds a file container with a geometry cache, and adds Rhai scripts with a Scripts menu and a command-line runner.

- **Large meshes:** Import Mesh reads STL, OBJ and 3MF, streaming the file and sharing vertices as it goes, and repairs the result (degenerate and duplicate triangles dropped, orientation made consistent, closed shells turned outward) with a report. Meshes are indexed, picked through a bounding-volume hierarchy, drawn from indexed GPU buffers, and bodies over two million triangles draw a coarse copy while the view moves. On the development Mac a 3.5 million triangle scan imports in 1.3 s, saves and reopens in 0.6 s, and picks in a fraction of a millisecond.
- **Mesh editing:** the Mesh menu adds Repair (with hole filling), Decimate (quadric edge collapse, or clustering for huge scans), Smooth (Taubin), Subdivide (Loop or midpoint), Cut by a plane (capped, one side or both), Mirror, Offset / Thicken (a closed shell becomes hollow, an open surface becomes a printable solid) and Sculpt (pull, push, inflate, smooth, flatten brushes; each click is a stroke in the timeline). Relief from Image builds a height field from a photo or a depth map; inverted and thin it is a lithophane. Over the command API the same operations take regions (sphere, box, plane side, normal cone, connected shell) and `mesh_measure` reports shells, open edges, watertightness, volume, area and wall thickness. Every operation is a feature, so undo and edits are cheap however large the mesh.
- **Mesh booleans:** joining, cutting and intersecting meshes now splits only the triangles near the other surface and classifies the rest by connected patch, so a small tool against a million-triangle scan takes about a second instead of minutes. Results are repaired and small seam holes closed; a few open edges can remain on awkward seams, and the measure reports them.
- **Faces and edges by name:** every face of an exact body carries a tag saying how it was made (swept from a sketch entity, a cap, made by a fillet, hole, primitive and so on), carried through later operations by the kernel's history or by surface matching. Fillets, chamfers, shells, threads, text and face-based construction planes resolve their picks by tag first and by position only as a last resort, so a fillet follows its edge when the block it sits on grows, and an operation whose face has been removed reports an error instead of landing on whatever is nearest. Object info lists faces and edges with their tags and says how each feature's picks were found. Files from 0.3 learn their tags the first time they are opened.
- **File container and geometry cache:** a design with reference images, imported meshes or reliefs saves as a ZIP of `design.json`, the images and meshes in their own encodings, a manifest and a thumbnail. Plain designs still save as plain JSON. The container also carries a geometry cache of the built bodies when the file is a container anyway or the design takes a while to rebuild; a matching cache opens without a rebuild, is verified by CRC, kernel version, volume and bounds, and a file saved by a newer Ferrender can still be viewed and exported read-only from its cache. The first save of an old plain file that becomes a container keeps the original as `name (0.3 backup).ferr`. `docs/FILE_FORMAT.md` is the written specification.
- **Scripts:** Rhai scripts with declared inputs run from the Scripts menu through an inputs dialog, on a worker thread with progress and Cancel, as one undo step, leaving a chip in the timeline that owns what the run made and can re-run with new inputs, detach or delete. Every command of the API is a function in a script; files are reachable only in the script's folder, the design's folder and folders you allow. Six samples ship (export variants of a parameter, export a folder of designs, a spur gear, bosses at sketch points, a CI check, a face relief); Export Timeline as Script turns a design into a generator. Headless, `ferrender run` and `ferrender check` serve CI, and MCP gains `list_scripts` and `run_script`.

## Compatibility and known limits

Older designs remain readable. The container is format 9, face and edge tags format 10, mesh operations and reliefs format 11, script runs format 12; a plain design that uses none of these is still written at its old version. Older apps refuse newer formats rather than silently omit features, except that 0.4 shows newer files read-only from their cache.

Mesh booleans are the previous BSP algorithm made to scale rather than an exact-predicate retriangulation; seams on very fine meshes can leave a few open edges, which Repair closes when they are small. Subdivision applies to a whole mesh, not a region. Relief images are normalised to 8 bits, so a relief has 256 height levels; a 16-bit depth map loses precision. Reliefs from a plain photograph use its brightness as height, which is a lithophane, not a likeness; a depth map made elsewhere gives a bas-relief. Script shortcuts (`META.shortcut`) are not bound to keys yet, and `confirm`/`ask` from a script running in the app take their headless answers (yes, and the default). The geometry cache is keyed on the whole design, so any edit rebuilds from scratch as before. Vertex picks for three-point planes and hole entry points stay position-based. Bodies with modeled threads are not cached.

## Verification and documentation

The local macOS suite passed **343 tests** (176 in the engine, 167 in the app), with zero failures and three optional demonstrations skipped. Coverage includes the container and its hostile inputs, the all-features format fixture, large-mesh import and picking against real scans (`crates/fr-core/tests/stress.rs`), tags following edits, the cache round trip and rejection, every mesh operation, booleans against the old algorithm's volumes, the sandbox and limits of scripts, all six samples headless, and the Scripts menu in the UI harness. The face relief was produced from a photograph over the MCP server end to end and is written up in `docs/tutorials/FACE_RELIEF_0.4.md`.

See the [manual test plan](TEST_PLAN_0.4.0.md), the [file format](../FILE_FORMAT.md), the [0.4 plan with what shipped](../0.4-release.md) and the [face relief tutorial](../tutorials/FACE_RELIEF_0.4.md).

Downloads include **Apple Silicon macOS**, **Intel macOS**, and **Linux x86-64**, with SHA256 checksums, documentation, and dependency notices. Linux builds target Ubuntu 24.04 and require glibc 2.39 or newer. macOS builds are ad-hoc signed, not notarized. Use **Help → About Ferrender → Copy build info** to verify version and source commit.
