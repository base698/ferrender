# Ferrender 0.3.0 manual test plan

This is the **Ferrender 0.3.0 regression and manual acceptance plan**. For future testing, report **Pass**, **Fail**, or **Unsure** by number. Allow about 90–120 minutes; you can stop between sections. Acceptance observations are recorded below; a listed check does not by itself imply every substep was exercised.

Save open work, quit older Ferrender windows, and open Ferrender 0.3.0. Use separate test files and keep your existing designs unchanged. Check **Help → About Ferrender → Copy build info**: it should say **0.3.0**, with the commit matching the release bundle's build information. Record the commit and whether the build includes local changes.

## Components

Selecting a component or editing one of its sketches does not activate it. Use its Activate control before making a sketch-based extrusion; new features belong to the active component. Directly extruding a picked body face follows that body's owner.

1. **Create and activate a component.** In a new millimeter document, choose **Model → New Component** or the **Component** toolbar button. Rename it `Bracket`. Confirm it becomes active, its name appears in the status bar, and its browser node contains Origin, Construction, Sketches, and Bodies sections. Draw a 20 × 10 mm rectangle on its XY plane and extrude 10 mm as New Body. Expect the sketch, extrusion, and `Body1` to belong to Bracket.
2. **Keep overlapping components separate.** Choose **Model → Activate Root**, then create another component named `Insert`. Draw the same 20 × 10 mm rectangle at the same coordinates and extrude 10 mm with **Join**. Expect two overlapping bodies, one in each component, with a `Body1` in each. Hide Bracket to inspect Insert. A Join in Insert must not consume Bracket's body.
3. **Scope a cut.** With Insert active, make a circle inside its rectangle and cut through all. Expect only Insert to have the hole. Hide Insert and show Bracket: its original box must remain intact. Undo the cut and Redo it. Check the browser and timeline still show the correct ownership.
4. **Nest and hide a subtree.** Activate Bracket, create a child named `Pin`, and make a small separate body in it. Hide Bracket: Bracket and Pin must both disappear, while Insert remains visible. Show Bracket: both return. Hide only Pin: Bracket must remain visible. Save and reopen; confirm nesting, visibility, and the active component survive.
5. **Move the whole component.** Select Bracket's component node and choose **Move**. Enter Translate X `30 mm` and Rotate Z `90 deg`; accept. Expect Bracket and Pin to move together, while Insert stays in place. Undo and Redo. Moving the component should edit its placement, without adding an ordinary body Transform feature. Select a body instead and open Move to confirm the body and component choices are distinct.
6. **Model on a moved face.** Keep Bracket moved and rotated, and explicitly activate Bracket before creating the sketch. Click a flat face of its body and start New Sketch. Draw a small circle and extrude it outward 3 mm. Expect the new feature to start exactly on the visible face and remain in that component. Move Bracket again: the new feature should travel with it. Check Measure and exports use the visible, placed positions rather than the original origin.
7. **Pattern and explicit Combine.** First run the [projection and corner-pattern retest](retest-projection-pattern.md). In a separate copy, pattern an Insert body; copies should belong to Insert. Try Linear with two directions, counts 2 × 2 and corner-to-corner spacings; expect four copies including the original. Double-click the pattern chip and edit the second spacing; Undo should restore its previous value. Position a tool body from another component so it overlaps the target and use **Combine** explicitly. Expect the result to stay in the target's component. With Keep Tools off, the consumed tool must disappear from its component; with Keep Tools on, it must remain. Undo should restore the original ownership and bodies.
8. **History and deletion.** While a child component is active, roll the timeline back before its creation. Expect its body to disappear and the active component to return to root with an explanation. Restore the marker to the end. Suppress a parent component: its descendants must not build; unsuppress it to restore them. Delete a parent from a saved copy: the confirmation should identify the subtree being removed, and other components should survive. Undo should restore the subtree. During marker dragging the model should remain unchanged until drop, as in 0.2.2.

## Construction planes

Use a fresh root-only document for tests 9–14. Make a **40 × 20 × 10 mm box** with its bottom on XY and save it as a reusable starting point. The Plane toolbar button and **Model → Construction Plane** open the same tool. Rotate the view as necessary to pick faces clearly.

9. **Offset from a face and use the plane.** Open Construction Plane, choose **Offset**, pick the box's top face, and enter Distance `5 mm`. Expect a preview 5 mm above the face and a new item under Construction after OK. Start New Sketch on that plane, draw a 6 mm diameter circle above the box, and extrude 3 mm as New Body. The post should span Z = 15–18 mm. Edit the box's original extrusion from 10 to 20 mm: the plane and post should move to Z = 25 and Z = 25–28 mm. Undo/Redo should restore/reapply the change.
10. **Edit offset, arrow, parameter, and To face.** In the offset dialog, drag the arrow and check the displayed distance and preview move together. Try `-3 mm` from the top face: the plane should be inside the box. Create parameter `gap = 5 mm`, set the distance to `$gap`, then change gap to 8 mm; its dependent sketch and post should move by 3 mm. Use **To face** to set the offset from one parallel box face to the opposite face. Confirm the preview lies on the chosen target face. Try a perpendicular target face: expect a message asking for a parallel face, with the previous distance unchanged. Cancel a further edit and verify the original plane is unchanged.
11. **Midplane and Flip.** Create a Midplane between the top and bottom faces. Expect it at half the box's height. Start a sketch on it and make a 4 mm symmetric cut; inspect a section or side view to confirm it is centered. In a fresh copy, choose top and side faces instead: expect a 45° bisector through their shared edge. Flip should choose the other bisector. Selecting the same face twice should show an error and create nothing.
12. **Three Points.** Create a plane from three noncollinear box corners that are not all on one box face; for the 40 × 20 × 10 box, use `(0,0,0)`, `(40,0,0)`, and `(0,20,10)` if entering coordinates. Expect the plane to pass through all three points. Start a sketch on it and make a small extrusion or cut. Repeat using three picked vertices, then a visible sketch point as one reference. Editing that source sketch point should move the plane. Three collinear or repeated points should be refused without changing the previous model.
13. **Picking, visibility, and chaining.** Create an Offset from another construction plane. Change the first plane's distance and confirm the second follows. Pick a construction plane from both the browser and viewport to start a sketch. Finish a sketch on a plane whose eye you have never toggled: it should hide automatically. Show it explicitly with its eye, make and finish another sketch on it: it should remain visible. Hidden planes must not intercept picking; a body in front of a plane must receive the click. The rectangle's edges must not become sketch geometry. Try selecting a construction plane with a nonzero quick Offset in New Sketch: expect an instruction to clear it or create another Offset plane. Clear it or enter zero, then select again: the sketch must stay attached.
14. **Broken references must be clear.** Save a copy and delete the original box extrusion. Its face-based planes should show errors, as should their dependent sketches and modeling features. The dependent solids must not silently remain at their old positions. Undo should restore the model. Separately suppress a source plane and restore it; its dependent solids should disappear and then rebuild. A failed plane should have an actionable message when inspected or edited. Also create a body Move after a plane, then edit the earlier plane: face picking and preview must show the body as it was when that plane was created; accepting must preserve the later Move.

## Combined checks and regression

15. **Planes inside moved components.** In a component, create an offset from its XY origin and a sketch/extrusion on it. Translate and rotate the component; its plane, sketch, and body should move together. Edit its plane distance and confirm the change follows the component's local normal. Create a plane referencing a face in a different moved component; moving that source component should update the reference correctly. Nothing should jump back to the document origin when picked or edited.
16. **Save, reopen, and export.** Save a document containing nested components and each plane kind. Reopen it and check names, active component, placements, visible state, parameter expressions, and sketch attachments. Export visible bodies to STL and STEP; check the files include the intended placed solids and omit hidden subtrees and plane rectangles. A component-filtered API export, if you test it, should contain only that subtree. STEP is a flat collection of solids, not an assembly hierarchy. Open a copy of a new-feature `.ferr` in 0.2.2: expect the readable “newer version” refusal.
17. **Existing designs and sketch tools.** Open a known-good bishop, rook, or pawn from 0.2.2. Check dimensions and exports. Quickly recheck endpoint-first three-point arcs, Dimension on an existing line, a persistent Shift angle lock, moving/scaling a reference image, open-end highlighting, invalid expression feedback, and Light/Dark/System appearance. Reopening an older design must not create extra components or change its shape.

## Solid primitives

These checks cover the additional solid tools in Ferrender 0.3.0. See the [primitive guide](../../adrs/0004-solid-primitives.md) for placement conventions. Allow another 20–30 minutes and use a fresh document or copies of the examples below.

18. **Create all five shapes.** Use **Model → Primitives** to create a Box, Cylinder, Sphere, Cone and Torus. Space them apart with Position X, for example 0, 50, 100, 150 and 200 mm. Expect a live preview, **New Body** as the default, five separate bodies and one timeline chip per primitive, without extra sketches. Check the Primitive toolbar opens Box and the Shape list changes the available dimension fields. The default cone should have a pointed top; the torus should have a clear hole.
19. **Check dimensions and placement.** Create a Box with Width `30 mm`, Depth `20 mm`, Height `10 mm` and Position `(5, 7, 9) mm`. Before rotation, it should span X = 5–35, Y = 7–27 and Z = 9–19 mm. Change Rotate Z to `90 deg`: expect X = -15–5, Y = 7–37 and Z = 9–19 mm. A cylinder or cone starts at its base center and extends along positive Z. A sphere or torus is centered at Position and extends both above and below it. For a torus with Major radius `15 mm` and Tube radius `5 mm`, expect 40 mm outside diameter, 20 mm hole diameter and 10 mm height.
20. **Units, parameters and editing.** Create a Box with Width `span = 1 in`, Depth `10 mm`, and Height `8 mm`. Expect a 25.4 mm width. Change parameter span to `32 mm`: the box should widen. Double-click its timeline chip, change Depth to `12 mm`, and accept. Expect the same feature to update, without adding another body. Undo and Redo should restore the dimensions. Save and reopen; expressions and parameter links should still work.
21. **Cancel and invalid inputs.** Open a Sphere preview and cancel: no feature or body should be added. Try Box Width `0 mm`, Cylinder Diameter `-2 mm`, an unknown parameter, a cone with both diameters zero, and a torus with equal major and tube radii. Expect a visible error and no accepted change. Correct the input and confirm the error clears. Repeat an invalid edit on an existing primitive; its prior valid shape must remain intact, including after Cancel. An invalid `bad = 0 mm` size must not leave a new parameter behind.
22. **New Body, Join, Cut and Intersect.** Start with a 20 mm Box at the origin. Make another overlapping Box as New Body: expect two distinct bodies. Undo it, repeat with Join and expect one combined body. Undo, add a Cylinder with diameter `6 mm`, height `30 mm`, Position `(10, 10, -5) mm` and Operation Cut: expect a through hole. Undo, then use an overlapping Box with Intersect and expect only the common volume. Confirm previews agree with the result after OK and Undo restores the previous solids.
23. **Components and local coordinates.** Make a Box in Root and an overlapping Box inside a new `Insert` component. Join or Cut in Insert must leave Root's box unchanged. Move Insert by X `50 mm` and Rotate Z `90 deg`; create a Sphere in Insert at local Position `(40, 0, 5) mm`, diameter `10 mm`. Expect its visible center at world `(50, 40, 5) mm`. Hide Insert: its primitives should disappear together. Show it and confirm they return at the same positions.
24. **Pattern and history.** Select a primitive and open Pattern. Make a Linear pattern with two directions, counts 2 × 2, and spacings large enough to separate the copies. Expect four copies including the original, all in the source's component. Edit the original dimensions; all copies should update. Double-click the pattern and change a spacing; expect the existing pattern to update. Undo/Redo, suppress/unsuppress the primitive, and move the timeline marker before/after it. Dependent pattern geometry should disappear and return coherently.
25. **Faces, appearance and export.** Sketch on a primitive Box or Cylinder's flat face and extrude a small feature; verify it starts on the visible face, including inside a moved component. Apply a small fillet or chamfer to a Box edge. Inspect the primitive gallery and an open dialog in Light and Dark appearance: inputs and preview edges should remain readable. Save and reopen the result, then export STL and STEP and inspect the sizes and placements. Hidden components should stay excluded. A copy opened in an older build should report that its format is newer, not silently lose primitives.

## Direct modeling and graphical placement

These checks cover body operations and graphical placement. See the [direct modeling guide](../../adrs/0007-direct-modeling.md) for coordinate frames and snapping behavior.

26. **Remove the original cone while keeping its mirror.** Create a cone away from the origin, for example Position X `20 mm`, and mirror it across YZ. Select only the original cone and use Remove Body. Expect the original to disappear at the new Remove timeline step while the mirrored cone remains intact. Roll back before Remove to see both, restore the marker, then Undo/Redo. Edit the Remove selection and Cancel; the previously accepted result should remain unchanged. The examples `01-cone-before-remove.ferr` and `02-cone-mirror-preserved.ferr` show the starting and expected stages. Optionally repeat with a box and a separated Linear pattern to check other earlier copies survive too.
27. **Split and rejoin.** Create a box crossing an origin plane, or make a construction plane through its middle. Split Body with that plane and expect two separate pieces. Move one piece to confirm they are independent, then Undo the Move and Join Bodies to reunite them. Repeat using a flat face from another body: the whole infinite plane should cut, regardless of that face's displayed size. A plane outside the body or a curved face should be refused with a clear message. Check Cancel and Undo preserve the prior solid. Follow `03-box-ready-to-split.ferr`, `04-box-split.ferr`, `05-split-piece-moved.ferr`, and `06-split-pieces-joined.ferr` for each stage.
28. **Move arrows and transaction boundary.** Open Move on a body and drag each colored X/Y/Z arrow. Expect only that translation field to change, the preview to follow, and the camera to stay still. Hold Shift and check movement becomes finer. Release, inspect the values, and Cancel: the original model must return. Repeat and press OK: one Undo must restore the complete move. Repeat on a component containing a child and on a body inside a rotated component; movement must follow the correct parent or owner axes.
29. **Rotate around the visible center.** Use a rectangular body away from the origin. Drag a rotation ring by roughly 90°: the body should turn around its center without orbiting the document origin. Hold Shift for 15° steps. In a top or side view, exercise the labelled rotation bars and depth arrow. Recheck the numeric fields, Cancel, OK, Undo, and both themes. For a component, its origin is the pivot; for a primitive, Position is the pivot.
30. **Graphical primitive placement.** Open a Box or Cylinder and choose Place in view. Click positions on XY, XZ and YZ, then try a picked flat face and a construction plane. With Align on, local +Z should match the chosen plane normal; with Align off, the prior rotation should remain. Refine the position with arrows/rings and accept. Repeat inside a moved/rotated component. Change the picked reference afterward: the primitive should retain the captured numeric placement. Cancel a new placement and confirm it adds no feature.
31. **Pattern last-copy span.** Create a Linear pattern with Count 4 and drag the last-copy handle to an overall span of about 30 mm. Expect spacing about 10 mm. Capture a visible sketch point or line and check the last copy aligns along the selected axis only, preserving its other coordinates and elevation. Try a circular arc and a negative direction. Enable a second direction for a grid and adjust each handle separately; changing one must leave the other spacing unchanged. Edit an existing pattern, Cancel once, then accept and Undo. Orbit when the direction is end-on. Use `07-pattern-sketch-targets.ferr` as a starting point and compare with `08-pattern-grid-aligned.ferr`.
32. **Sticky sketch placement and release.** While drawing lines and circular geometry, approach an existing line, arc, circle, and endpoint. Expect capture near the target, enough tolerance to click it, and a visible highlight. Move farther away, make an outward flick, or hold Alt to release. Click while captured, then edit the target: the supported coincidence or point-on-curve relationship should remain. Check spline endpoints capture but spline interiors do not claim a point-on-spline constraint. Repeat at different zoom levels and with nearby competing targets.
33. **Interrupted gestures and saved results.** Begin a handle drag, then cancel or switch dialogs; the old gesture must not alter the next tool or orbit the camera unexpectedly. Save and reopen accepted Remove, Split, Move, placed primitives and edited patterns. Check their history, expressions, visible placements and component ownership, then export STL and STEP. Compare the exact build information with the tested release and retain any failing file.

## Command search, text, and rounded-face cuts

34. **Search commands with S.** In model mode, press **S**, type `torus`, and press **Enter**. Expect the Torus dialog to open with a preview; Enter must not also accept the new feature. Cancel, reopen search, type `text` or `emboss`, and confirm Text / Emboss is offered. Use the arrow keys to select a result and Escape to close search. Try an unmatched query: no unrelated command should run. Repeat from an active sketch; **V** should choose Select. Commands that require a selection should explain their prerequisite. Typing S or M in a name, text field or dimension must enter the letter rather than launch a tool.
35. **Move with M.** Select a body, press **M**, and check Move opens for that body. Cancel, select a parent component, press M and check the component and its children preview together. Accept and Undo once. Press M with nothing selected: expect a helpful selection message or an available target, with no unintended move.
36. **Find and place text.** From a sketch, use **S → Text / Emboss**. Expect to leave sketch editing and enter the solid lettering dialog. Create `TEST` as a New Body on XY, height `5 mm`, depth `1 mm`, and inspect it. Then use a fresh 40 × 20 × 10 mm Box: select its top face, open Text / Emboss, place a short label entirely over that face and choose Join. Expect raised letters. Repeat with Cut for engraving. Save/reopen and edit the lettering in the timeline. Curved faces should give a clear unsupported-face message.
37. **Cut and extend a rounded end face.** Create a 30 × 15 × 20 mm Box, fillet two long opposite edges at `2 mm`, select an end face perpendicular to those edges and extrude inward with Cut. Inspect closely: the cut should leave a clean rounded end, without thin strips extending along the removed section. Undo and extend the same face outward with Join. Check the rounded outline is smooth and the accepted result matches the preview. Repeat on a cylindrical end face and a face with a circular hole. Keep a copy of your earlier failing file; existing frozen face sketches are not automatically rewritten.
38. **Body Boolean operations and torus.** Use separate copies of the supplied `weird-joins-corrected.ferr` for Combine → Join, Cut, and Intersect. Select the intended target and torus tool explicitly; reverse target/tool for a second Cut. With Keep Tools off, only the result should remain; with it on, the tool should remain selectable and may visually overlap the result. Undo must restore both originals. Repeat with two partially overlapping Boxes for an easy shape comparison. For disjoint bodies, Combine → Intersect has an empty result: the target disappears and the tool remains only if Keep Tools is on. Undo must restore both. Primitive → Intersect instead refuses a tool that does not reach an existing body. Save/reopen the accepted results and inspect STL or STEP exports.

## Recent designs and settings

39. **Open Recent and restart.** Save two different designs with Save As. Choose **File → Open Recent**: the last saved design should be first. Open the older entry and confirm it moves to the top without a duplicate. Quit and restart Ferrender; the list should persist. Try two files with the same name in different folders; their folder labels and full-path hover text should distinguish them. With unsaved edits, choose a recent design and cancel the discard prompt: your edits should remain. Move a recent file away temporarily and try opening it: expect a visible error and the current design to remain. Restore the file and retry. **Clear Recent** should empty the list after restart without deleting any designs. Settings remain in `~/.config/ferrender/config.toml`, and history is in `recent.json` beside it; `FERRENDER_CONFIG_DIR` and `XDG_CONFIG_HOME` are honored. A failed open/save, STL import, or export should not add a recent design.

## Manual observations received

On October 8, 2026, the user accepted component checks **1–8** and the reported workflows for command search, Move shortcut, raised/engraved text, rounded-face extrusion/cutting, torus Boolean operations, and Open Recent (**34–39**). The initial component isolation checks used Root and Bracket rather than a separate sibling Insert component. The user also reported successful Remove/STL export, Split, moving/rotating separated and rejoined bodies, sketch capture on lines/projections, and sketch/extrude workflows on Offset and Three Points planes. These observations record the tested workflows, without claiming every optional substep or negative case was run manually.

The user approved publishing 0.3.0 once CI passes. Automated coverage complements the manual observations. Separate bodies with overlapping coplanar faces can still show a display artifact; joining them removes coincident internal surfaces. This known display limitation remains documented for the release.

## Report a failure

Send the number, copied build info, exact inputs, expected result, actual result, and any error text. Save the smallest `.ferr` that reproduces it; include a screenshot for picking, placement, visibility, or layout problems. Say whether the action was refused, made the wrong shape, or changed unrelated geometry. Keep any failed example so it can become a regression test.

Retain this checklist for future regression testing. Release builds are published only after the required CI and native packaging checks pass.
