Ferrender 0.2.0 improves sketching from measured points and photographs:

- **Point Coordinates…** creates or edits points using signed X/Y length expressions. Position dimensions keep parameter-driven locations editable.
- **3-Point Arc** uses start, through, and end points. **Tangent Arc** continues from a line or circular arc endpoint.
- **Spline** creates an editable native curve through four fit points, usable in closed modeling profiles and exact STEP solids.
- **Reference Image…** embeds a PNG or JPEG on the sketch plane, with placement, opacity, and two-point scale calibration.
- **Highlight Open Ends** marks unconnected outline ends with orange rings and a count.
- Scientific notation works in number expressions and API coordinates, including the near-zero values encountered while constructing the pawn.

The [bishop tutorial](https://github.com/base698/ferrender/blob/v0.2.0/BISHOP_TUTORIAL.md) now uses direct coordinate entry and three-point arcs. The archive includes the [sketching guide and manual acceptance plan](https://github.com/base698/ferrender/blob/v0.2.0/docs/adrs/0001-sketching-tools.md), plus the preserved 0.1 tutorial for older builds.

These are focused first implementations: splines have four fit points, tangent arcs start from lines or circular arcs, spline Trim/Offset and curve constraints are limited, and an absence of open-end markers does not prove that an outline is free of self-intersections. Reference images are tracing aids and do not appear in solid exports. Calibration cannot remove perspective distortion from a photograph.

Existing `.ferr` files remain readable. Save a separate copy when testing files with new 0.2 features in older app versions.

Downloads:

- **macos-arm64.zip** — Apple Silicon Mac app.
- **macos-x86_64.zip** — Intel Mac app.
- **linux-x86_64.tar.gz** — Ubuntu 24.04 build; requires glibc 2.39 or newer and a desktop graphics driver.
- **SHA256SUMS.txt** — download checksums.

Each archive includes the native app, build identity, installation instructions, documentation, and dependency notices. macOS apps are ad-hoc signed, not notarized; use the normal macOS approval flow when opening a downloaded build.

The release workflow runs engine tests on all three platforms, the full offscreen UI suite on Linux, and a solid-modeling smoke check with each packaged executable. See **Help → About Ferrender** for the full source commit when reporting results. Native desktop interaction and the complete human bishop walkthrough still need manual acceptance; automated checks do not establish those results.

Local validation: 132 automated tests passed (three optional demos skipped), including offscreen drawing, coordinate editing, reference-image calibration and undo, native spline solids and STEP export. The revised bishop recipe produced one exact closed 30 mm body, and its 36 mm parameter check also passed.
