# Ferrender 0.3.0 test-build notes

**Testing candidate only. Not a published release.** User verification is required before tagging or publishing 0.3.0. Check **Help → About Ferrender → Copy build info** for **0.3.0-dev** and compare the commit with the test bundle's build information; a version number alone does not distinguish successive test builds.

The candidate work adds:

- **Components:** nested named containers for sketches, bodies, planes, and modeling features. The active component owns new work; Join, Cut, Intersect, and Through All are scoped to that component. Explicit Combine can reach across components.
- **Component placement and visibility:** move and rotate a whole component subtree, hide or show it, and preserve ownership through timeline changes, Undo, saving, and exports.
- **Construction planes:** Offset, Midplane, and Three Points features with persistent references. A sketch created on one follows its plane as parameters, source faces, or source points change.
- **Explicit extrusion profile selection:** sketches with multiple closed regions require an area selection, including projected outlines with new circles. Plain click replaces the selection; Shift-click adds or removes regions. New Body keeps the selected extrusion separate.
- **Native solid primitives:** editable Box, Cylinder, Sphere, Cone/frustum and Torus features under Model → Primitives, with parameter-driven sizes and placement, component-scoped operations, pattern support and exact STEP export.
- **Two-direction linear patterns:** rectangular grids with independent axes, counts and signed spacings, plus timeline editing of an existing pattern.
- **Browser and timeline controls:** component activation and nesting, a Construction folder, plane visibility, feature editing, and identification of feature ownership.

Native files that use components or construction planes use format 5. Two-direction linear patterns use format 6, so older candidate builds refuse them rather than silently drop the second direction. Primitive features use format 7. Use the matching 0.3.0 test build identified in About. Older files remain readable; plain documents continue to use the older compatible format when they do not need new features. Test with separate copies when comparing versions.

Joints, component instances, linked external components, STEP assembly structure, browser reparenting, moving an existing body between components, and dragging components in the viewport are outside this candidate's scope. Component movement uses its placement dialog. Construction axes, tangent/angled planes, and construction planes as arbitrary mirror or To Face targets are follow-up work.

Use the [consolidated manual test plan](../TEST_PLAN_0.3.0.md), [components specification](../COMPONENTS_0.3.md), [construction planes specification](../CONSTRUCTION_PLANES_0.3.md), and [primitive guide](../PRIMITIVES_0.3.md). The separate specifications retain their detailed design rationale and acceptance cases.

## Validation status

The focused app acceptance suite passes **11/11**. It exercises component creation through the Model menu, activation, nesting, inherited visibility, subtree deletion and Undo, modeling on moved component faces, all three construction-plane dialogs, parameter-driven plane attachments, invalid collinear input, visibility pinning, and plane editing at an earlier history position. Additional pointer-driven checks cover arrow dragging across zero, signed To face distances on a rotated component, nonparallel target refusal, vertex and sketch-point references, and plane picking that respects visibility and frontmost bodies. It also saves and reopens a native candidate fixture and renders Light and Dark screenshots; both have been visually inspected.

The full local macOS automated suite passes **231 tests**, with zero failures and three optional demonstration tests skipped. Six additional app tests reproduce projection, explicit region selection, repair of an existing bad extrusion, and two-direction pattern controls, editing and Undo. Seven core grid tests cover body separation, placement, parameter updates, malformed input, bounds, native round trips and legacy single-direction compatibility. The pattern dialog and four-corner result were rendered and inspected. Use the [focused projection and pattern retest](../RETEST_PROJECT_PATTERN_0.3.0.md) before continuing the main plan. No manual acceptance pass is claimed. Exact build identity, final full-suite results, artifacts, and remaining limits belong in the delivered test bundle's validation report. Native menus, picking, keyboard behavior, and the full human modeling workflow still require user verification even when automated tests pass.

The primitive addition passes six core tests and five app tests, covering the five solid types, exact volumes and topology, cone variants, placement and parameters, component-scoped operations, primitive patterns, construction-plane references and exact modifiers, native validation, editing and Undo/Redo, exports, and menu-driven previews. The primitive dialog was rendered and inspected in Light and Dark appearances. Human primitive acceptance is covered by checks 18–25 in the consolidated plan.
