### Integration fixes and native evidence

Script cancellation and deadlines are checked after the final host call and during publication. Invalid/overflowing time limits are rejected before session ownership moves. Output destinations are prepared before publication; ordinary publication failures restore previous outputs and conversion backups, retaining named recovery files if restoration fails. Regular-file checks cannot block on a FIFO, temporary files use restrictive permissions, and exported assets have content-derived names that refuse conflicting data. Export examines failed features beyond the rollback marker. This does not make several filesystem writes globally atomic across a crash or storage failure; Undo still does not remove outputs from a successful run.

The Intel job exposed a one-ULP fixture coordinate difference. Cross-platform fixture comparison now permits only machine-epsilon floating-point differences while preserving exact JSON structure, scalar types, integer identifiers and ordering. Per-platform serialization round trips remain exact, and a strictness regression guards the comparison. No fixture geometry was regenerated to hide the difference.

## Findings and remaining release boundaries

1. ~~**Complex mesh Booleans remain limited.** Closed-result checking catches known seam failures but is not a proof that every closed output has correct geometry. Some intersections now fail safely that the old implementation incorrectly claimed had succeeded. A robust-predicate solver remains future work.~~ **Solver gap fixed:** the BSP is replaced with Manifold, including exact rational arrangements. Analytic volume and solid-membership tests supplement topology checks, and the actual f32/STL representation is validated. Invalid operands, work limits and features below storage precision can still be refused; no finite regression suite is a proof for every possible input.
2. **Topology naming — concrete instability fixed; ambiguity remains open.** ~~Kernel-generated faces use ordinal identities, and script output order can redirect references.~~ New references use semantic/provenance identities, Boolean history through cleanup, boundary-qualified split pieces and explicit pattern copies. Script outputs use persistent keys rather than list position. Dimension/radius/thickness changes and inserted/reordered outputs have regressions. Truly removed or indistinguishable faces, generated topology without unique provenance, and ambiguous early-development tags can still need reselection. Vertex picks for three-point planes and hole entry points remain position-based. This narrower remainder is deliberately **not crossed out** as universal stability has not been established.
3. **Scripts are not an OS sandbox.** (The open script items are collected for 0.5 in [0.5-scripts.md](0.5-scripts.md).) Scripts run in the app's process: a native modeling call cannot be cancelled mid-call and there is no per-script memory budget or process isolation. *Narrowed by merged PR #2:* Cancel and a new time limit (`run_script` `"timeout"`, `ferrender run --timeout`) take effect at the script's next operation, and the progress window offers to stop waiting for a modeling call and discard its result; files a script writes are staged beside their targets and moved into place only when the run succeeds, with cancellation/deadline checks after the last host call and during publication; ordinary publication failures restore previous outputs, including compatibility backups (Undo still does not remove files a finished run wrote); the allowed folders are walked from their root without following links when a file is used, writes go through a fresh temporary and a rename, so a link or hard link planted on a target name is replaced rather than written through; `confirm`/`ask` are answered in the progress window. A crash or storage failure during rollback can require manual recovery from the named retained files. Exported scripts use the same staged publication, with content-named assets that refuse conflicting existing data. The sandbox bounds the script, not another program running as the same user, and native commands that read a file by path (`import_mesh`, `open`, `mesh_from_image`) check the entry immediately before the read rather than holding it open.
4. ~~**Cache integrity is not authentication.** CRC and geometric checks detect accidental damage/staleness. They do not authenticate a deliberately forged cache and index. Use a fresh rebuild when independently validating a supported downloaded design.~~ **Trust gap fixed:** supported geometry caches require HMAC-SHA256 authentication under a private installation key before adoption. Unsigned, foreign or modified files rebuild automatically, even when a forged cache and index agree. Newer unsupported files are visibly unverified previews, and exports retain that provenance. This authenticates local save provenance, not a publisher or an attacker who already possesses the private key.
5. **Large-mesh selection is incomplete.** Individual face highlighting is disabled above 200,000 triangles. Full-resolution picking and whole-body selection remain available. The plan's 5 M/12 M interactive frame-rate and reduction targets have not been established by these headless benchmarks.
6. **Script export has explicit limits.** *Narrowed by merged PR #2:* a timeline marker anywhere is exported in full and restored by the script; failed features are exported suppressed with a note; hidden body ids that no longer exist are dropped; imported meshes and embedded images above 64 KiB are written as STL and PNG files beside the script, which `add_feature` reads back through `mesh_path`/`image_path`. Still refused: a script that would exceed 1 MB after that (very long names or many large sketches) and integers beyond Rhai's 64-bit range. An STL sidecar carries the triangles in 32-bit floats, which is also how the inline form stored them.
7. **Deferred features remain deferred.** No region subdivision, mesh-region projection, META shortcut bindings, or 16-bit relief input was added by this review. (Interactive script confirm/ask is included through merged PR #2.) Relief from brightness alone is not reconstructed facial geometry.
8. **Native build verification has boundaries.** *Addressed by merged PR #1:* release-profile Cargo builds now fail unless `OCCT_ROOT` is the directory prepared from the pinned archive (or `FERRENDER_ALLOW_UNVERIFIED_OCCT=1` is set), the executable reports the result as an `OpenCascade:` line in About and `--version`, the packager refuses anything not reporting the pinned archive, and GitHub Actions are pinned to commit hashes. What remains: the line is the build's own statement rather than a signature, and it does not detect tampering by someone with write access to the build machine. See [RELEASING.md](../RELEASING.md).
9. **Dependency maintenance:** the locked-version RustSec scan matched two informational unmaintained notices: [smartstring 1.0.1 via Rhai](https://rustsec.org/advisories/RUSTSEC-2026-0249.html) and [ttf-parser 0.25.1](https://rustsec.org/advisories/RUSTSEC-2026-0192.html). No matched known security vulnerability was found in that scan. Database snapshot: `550efd3d587a29b2e2c2b21b17a440da4fede999`. *Addressed by merged PR #1:* text outlines now come from `skrifa`, the parser egui already uses; all 4,333 accepted cases and every rejection across U+0020–U+2FFF at two sizes were byte-identical to the previous output. The custom check is replaced by `cargo deny` in CI, which found the same two notices and nothing else. What remains: the locked Rhai 1.26.1 still requires smartstring, and on Linux `ttf-parser` is still linked through winit's Wayland title-bar renderer, where it reads system interface fonts rather than designs. Both are recorded exceptions in `deny.toml`.
10. **Platform/manual coverage:** current Apple Silicon, Intel macOS and Linux automated builds/tests/packaging passed as recorded above. Native desktop interaction was exercised on Apple Silicon; Linux/Intel desktop behavior, physical prints and continuous 5 M/12 M orbit frame rates remain unverified. The extra native closed-ring Sweep attempt was interrupted by a locked Mac; automated ring coverage passed. No release was made as part of this review.
11. **Sweep scope:** paths are planar sketches, with Follow/Fixed orientation and mitred sharp turns. Corners may turn by at most 150 degrees. Nonplanar/helix paths, profile scaling/twist guides and rounded mitres are not implemented. Tight bends, unsuitable profile planes and unsupported orientation/path combinations can be refused with a reason; the UI and kernel refusals have regressions.

### New defects fixed

- **Script Run disabled:** Scripts → Samples → Spur gear showed “Nothing to apply” and a disabled Run button with valid defaults. Scripts had incorrectly entered the modeling-preview path. They now use their worker action without a geometry preview, while Enter still runs them. The regression now clicks the real **Run** and **Run again** controls, rather than calling the action directly, and also checks Enter. Actual native Run and Run again passed after rebuilding.
- **Large-mesh crash recovery failed:** Beethoven imported normally, but autosave expanded it to legacy base64 JSON and exceeded the old 64 MiB limit. Recovery now stores the compact native JSON/ZIP payload in a bounded metadata envelope with length and CRC checks. Legacy recovery still loads; discovery reads only the header; synced atomic replacement preserves the previous copy when a write fails. A successful save also clears a stale failed-recovery warning. Thirteen recovery tests pass, covering a 1.5 M-triangle mesh with an embedded image, compatibility, corruption, bounded discovery, failed replacement and temporary symlinks. The real Beethoven fixture round-tripped identically in 0.697 seconds in the focused storage test.

Recovery payloads are limited to 2 GiB and metadata to 64 KiB. Encoding remains in memory on the background writer, so a large write may finish later than the one-second scheduling interval. Older Ferrender versions cannot read the new recovery envelope. CRC is accidental-damage checking, not authentication, and no universal power-loss guarantee is claimed.
